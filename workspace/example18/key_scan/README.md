# 4×4矩阵键盘扫描实验

## 文件与兼容性

- `test_all.c`：新增的用户态扫描程序。
- `Makefile`：只编译 `test_all`，不重编译驱动。请放在独立目录中，不要覆盖原实验的 Makefile。
- 复用 SuccessCode/example18 已成功使用的 `key.ko` 和 `/dev/key`。原成功项目不作修改。

GPIO103—106为行输入，GPIO107—110为列输出。程序按1000、0100、0010、0001依次选通，每列等待约1毫秒后读取8个int，取前4个行状态；切列前先将全部列置低。完整扫描后稍作等待并重复，消抖约30毫秒。Linux用户态调度可能延长这些时间，不属于硬实时扫描。

## 1 在Linux主机交叉编译

将本目录复制到Linux主机，进入目录执行：

```sh
make
file test_all
```

Makefile采用指定配置：

```make
KDIR := /home/user/loonarch/linux-5.10-2k500-cbd-src
ARCH := loongarch
CROSS_COMPILE := loongarch64-linux-gnu-
CC := $(CROSS_COMPILE)gcc
```

本次只新增用户程序，因此编译时实际不依赖KDIR。将生成的test_all和原有成功版本key.ko放入U盘，在开发板挂载U盘后，通过MobaXterm进入该目录。以下命令均在开发板执行，不是在Linux编译主机执行。

## 2 加载驱动

先退出原来的test_key，确保只有一个程序使用/dev/key。驱动未加载时执行：

```sh
insmod key.ko
ls -l /dev/key
```

已经加载则不重复insmod。若U盘挂载为noexec或只读，可将程序和后续校准文件放在开发板可执行、可写的目录运行。

## 3 首次进行实物位置校准

```sh
./test_all --calibrate
```

先松开全部按键，然后按终端提示依次按下16个按键：第一行从左到右，再第二行、第三行、第四行。每次只按一个，按住至显示Accepted后松开，再按下一键。这里的第一行指你面对实验箱时最上方一行，第一列指最左侧一列。

校准会在当前目录生成keymap.conf，保存物理位置与GPIO交点之间的对应关系。重复按已登记按键会提示重试。校准不是修改接线，也不会修改驱动。若中途Ctrl+C退出，旧校准文件保留。

## 4 直接运行

在keymap.conf所在目录执行：

```sh
./test_all
```

默认每500毫秒追加输出一次当前4×4状态。1表示按下，0表示松开。例：实际第二行、第三列被按住时：

```text
[t=1000 ms]  1=pressed, 0=released
      C1 C2 C3 C4
R1    0  0  0  0
R2    0  0  1  0
R3    0  0  0  0
R4    0  0  0  0
Pressed: R2C3
```

可调整为每1秒输出一次：

```sh
./test_all 1000
```

允许100—60000毫秒；此参数仅调整打印间隔，不调整扫描周期。没有校准文件时程序会提示先校准，不会将未经确认的GPIO顺序冒充物理位置。若需从其他目录启动，可设置KEY_MAP为校准文件的实际路径。

Ctrl+C正常退出时，程序将四路列输出恢复为低电平。不要用kill -9作为正常停止方式，因为无法执行清理。确认程序退出后可执行rmmod key。

## 5 展示与验证

1. 不按任何键，确认4×4全为0。
2. 按住左上、右上、左下、右下四角各约1秒，确认分别显示R1C1、R1C4、R4C1、R4C4。
3. 逐个验证其余位置；松开后应恢复0。
4. 使用默认500毫秒和1000毫秒间隔分别观察输出。
5. Ctrl+C退出后重新启动，确认可复用校准文件。

本版沿用原驱动“选中列输出高、其他列输出低”的方式，按单键实验使用，不支持或保证多键同时按下的识别。请勿将多键结果作为验收依据。矩阵显示当前稳定状态而非按键事件历史；短于输出间隔的按压可能发生在两次打印之间，展示时建议按住约1秒。

发言参考：“原实验需要手动选择某一列。本次扩展由程序自动轮流选通四列，再读取GPIO103到106的行电平，将扫描结果映射到与实物排列一致的4×4矩阵。现在按下第二行第三列，可以看到矩阵对应位置变为1，松开后恢复为0。软件消抖用于减少机械触点抖动造成的状态跳变。”

## 验证范围

已依据现有key.c核对读写接口；开发环境使用模拟GPIO接口检查16个交点、空闲状态、按下/松开消抖、短读错误及列复位。不包含真实开发板测试，LoongArch交叉编译和实际按键效果需在目标环境确认。
